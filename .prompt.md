# Prompt: Project Assignment Fulfillment (Workspace-scoped; Deliverables, Materials, Blueprint)

Purpose
-------
This workspace-scoped prompt instructs an assistant to generate a complete "fulfillment package" for a project assignment: a concise summary, acceptance criteria, deliverables list, a technical blueprint of the solution, all required materials, a file manifest (what to create), example code/notebooks, a test & QA plan, and a submission checklist. When `workspace_scoped=true` the assistant should prefer and reuse existing repository files and project context provided via `project_root` and `existing_files`.

Core task pattern (extracted from recent work)
--------------------------------------------
- Core task: Convert a project assignment or specification into a concrete, runnable set of deliverables and a technical blueprint.
- Implicit inputs: assignment text, target platform/language, constraints, and any existing files or notebooks from the workspace when provided.
- Desired outputs: machine-readable manifest (JSON) + human-readable sections (Markdown), example file contents, and minimal runnable artifacts.

When to use this prompt
-----------------------
- You have a project assignment (class/homework/client brief) and need a complete plan + deliverables to implement and submit.
- You want the agent to produce files, blueprints, and materials ready to drop into a repo and to reuse existing project code when available.

Template prompt (workspace-scoped, copy-paste and replace placeholders)
--------------------------------------------------------------------
Use this exact prompt when talking to the assistant; replace <<ASSIGNMENT>> and flags.

```
You are an expert software engineer and project lead. Given the following project assignment text and the workspace context, produce a complete fulfillment package that a developer/team can implement and submit.

Assignment:
<<ASSIGNMENT>>

Workspace context (optional but recommended when `workspace_scoped=true`):
- `workspace_scoped`: true|false (if true, assistant may/read SHOULD read repository files listed below)
- `project_root`: path to repository root (e.g., `.`)
- `existing_files`: an array of workspace-relative paths the assistant should open and reuse (e.g., ["README.md","support_ticket_triage.ipynb"]).

Flags/Parameters (optional, defaults shown):
- `depth`: `high|medium|low` (default: `high`) — level of detail for blueprint and files
- `language`: preferred implementation language(s) (default: `python`)
- `include_files`: `true|false` (default: `false`) — whether to output full file contents
- `include_code_examples`: `true|false` (default: `true`)
- `timeline`: desired overall timeline (e.g., `1 week`, `2 sprints`)

Output requirements:
1. Provide a one-sentence `summary` of the assignment.
2. Provide `acceptance_criteria` (list of verifiable criteria).
3. Provide a `deliverables` list (what to hand in).
4. Provide a `blueprint` section with architecture, data flow, and a mermaid diagram when applicable.
5. Provide an `implementation_plan` with milestones, steps, and estimated hours per task.
6. Provide `materials` and resources required (datasets, libraries, credentials, readings).
7. Provide a `files` manifest: for each file include `path`, `purpose`, and a short `snippet` or full content if `include_files=true`.
8. Provide a `tests` plan: unit/integration tests and acceptance tests.
9. Provide `deployment`/CI instructions and minimal commands to run locally.
10. Provide `risks` and `mitigations`.
11. Provide a `roles` suggestion (who should do what).
12. Provide a `packaging` section explaining the final submission format and checklist.

Produce two artifacts in your reply in this order:
A) A machine-readable JSON object exactly matching the schema (see schema block below).
B) A human-readable Markdown section with the same content expanded and a `README.md` ready to paste.

If information is missing or ambiguous, first list the clarifying questions you need, then stop.
```

```
  "blueprint": { "description": "", "mermaid": "" },
  "implementation_plan": [ {"milestone":"","tasks":[{"task":"","estimate_hours":0}] } ],
  "materials": [],
  "files": [ {"path":"","purpose":"","snippet":""} ],
  "tests": { "unit_tests": [], "integration_tests": [], "acceptance_tests": [] },
  "deployment": { "local_commands": [], "ci": "" },
  "risks": [],
  "roles": [],
  "packaging": { "submission_format":"", "checklist": [] }
}
```

Ambiguities the assistant should ask about (examples)
----------------------------------------------------
- Preferred implementation language(s)? (default: `python`)
- Target runtime/platform (Linux server, serverless, browser, mobile)?
- Any forbidden libraries or licensing constraints?
- Available datasets or sample data?
- Deadline or desired timeframe?
- Team size / who will implement?

Example invocation (short)
--------------------------
Input (assignment): "Build a REST API that ingests CSV user data, validates it, and stores cleaned records in a PostgreSQL DB. Provide a small frontend to upload files and show validation errors."
Flags: `depth=high`, `language=python`, `include_files=true`, `timeline=1 week`, `workspace_scoped=true`, `existing_files=["support_ticket_triage.ipynb"]`

Expected top-level outputs:
- JSON `summary`, `deliverables` including `api/`, `frontend/`, DB schema, tests, and `README.md` content.
- `blueprint.mermaid` showing client -> API -> DB flow.
- `files` entries for `README.md`, `api/main.py`, `api/requirements.txt`, `frontend/index.html` with code snippets.

Iteration & refinement process
------------------------------
1. Analyze assignment and attempt to produce a complete draft using provided workspace files when `workspace_scoped=true`.
2. If required inputs are missing, list clarifying questions and pause.
3. After clarifications, produce final JSON + Markdown + files.
4. Optionally produce a git-style patch or zip manifest of files.

How to customize this prompt
---------------------------
- Workspace-scoped (recommended): pass `project_root` and `existing_files` so the assistant can reuse code already in the repo.
- Team-scoped: add `team_roles` and `skill_levels` so the assistant targets realistic estimates.
- Graded assignments: add `rubric` to align deliverables to grading criteria.
